# 五项补充实验：2026-11-21

本轮生成了五组 PDF、可编辑 SVG 和 600 dpi PNG。**热力图是局部生产算法的条件通过率，不是 Gazebo 避障成功率；完整 IK / MRT / WBC 联合准入的 64 格 × 100 次实验仍未完成。** 可直接支撑的结果是：生产候选的固定终端边界、所选实际多项式段的凸包几何差异，以及本次 Gazebo 中真实模型约束和安全过滤器的运行诊断。

数据目录：`data/extended_20261121/`；图目录：`figure/extended_20261121/`。原有六图和旧数据保留。

## 场景与运行

用户原场景八个障碍的中心 z 都为 0.03 m。按碰撞盒计算，名称 2/4/6/8/10/12/14/16 cm 对应的原始顶面实际为 4/5/6/7/8/9/10/11 cm。前两个还悬空。本轮不修改用户源场景；`prepare_sweep.py` 在实验副本中将中心设为各自高度的一半，使顶面确为 2–16 cm。逐个尺寸和源文件哈希见 `scene.json`。

`eight_heights.sdf` 是修正后的八档场景；`pilot.sdf` 仅将第一个模型别名设为既有采集器识别的 `thin_obstacle`，八个障碍均保留。障碍 X 位置仍为 −1.2、−1.6、…、−4.0 m，宽 0.03 m、长 1 m。

先导试验：随机种子 20261121，ROS_DOMAIN_ID=179，原地站立、trot、转向 180°，随后只给 normalized speed=0.4 的前进指令，目标 X=−4.35 m。HOCBF 和误差管均开启；没有调整机器人任务参数、增益、走廊范围或安全限值。约 46.761 s 在 X=−3.094 m、Y=0.754 m 跌倒。连续路线中姿态和位置误差会从前面障碍传递到后面，不能把一趟路线拆成相互独立的八次试验，也不能凭机身越过某 X 坐标认定某足端已安全通过。

因此启用用户允许的生产算法备选方式。实际 Gazebo 日志保留为独立证据，不伪造每格物理触地结果。本轮 390 条在线重规划决策中，首次实际应用次数为 0；不能据本轮数据声称已在 Gazebo 中展示“同一次摆动发现障碍后成功切换”。

## 实际摆动时序与扫描协议

- 原配置 trot 模式 LF_RH / RF_LH，切换时刻 `[0,0.4,0.8]` s。
- 从运行中的执行策略快照读取到 200 条摆动边界，时长均为约 0.4 s（浮点误差约 10⁻¹⁵ s），而非仅从 gait.info 推断。见 `runtime_schedule.json` 和 `wbc.jsonl.swings.jsonl`。
- 将 0.4 s 等分为八档剩余时间：50、100、150、200、250、300、350、400 ms。400 ms 对应抬脚入口；不是“摆动中途”的案例。
- 八档高度 × 八档时间 × 每格 100 个固定种子 = **6400 条完整请求记录**。
- 每格保留 0–99 全部试次；100 个种子跨格配对。每个种子选取一条实际 MPC 参考，并在配置的 1 mm 位置球、0.01 m/s 速度球、0.5 m/s² 加速度差球内独立抽样，障碍相对轨迹中点偏移 ±1 cm。这里的分布是明确规定的蒙特卡洛条件，**不是从 Gazebo 实测拟合出的误差分布**。
- 159 条来源参考满足完整 0.4 s、X 步长至少 25 mm、两端高差至多 8 mm、起点高度至多 45 mm；从同一次先导的转向和前进阶段采集。仅平移到局部地面和障碍坐标，保留实际样条形状、节点与导数。时间端点在 10⁻⁸ s 内吸附到已核验的 0/0.4，避免绝对时刻相减后触发生产走廊的严格端点检查。
- 直接调用生产 `loadSwingTrajectorySettings`、`buildTerrainSafetyCorridor`、`SwingOnlineReplanner::admit/instantiate`，没有使用上一轮机制测试的宽松参数。
- `swingReplanMinRemainingTime=0.12` s，因此 50/100 ms 档位按配置拒绝；短时入口不构造无效的剩余走廊。
- **范围边界：**此扫描没有重建每条参考对应的完整 IK 回调、机器人状态演化、MRT 传输/整包预算和 WBC 准入预览。它只检查生产候选与边界实例化子流程，不能称为完整控制器的可行域或成功率。当前源配置 `checkSwingReference=false / verifySwingOutput=false` 也照实保留，中段证书不能自动延伸到完整接触过渡段。

调试期间一次浮点端点校验中止保存在 `sweep_aborted_knot_roundoff/`，它的部分记录不纳入正式 6400 次统计；修正的是测试输入的端点舍入，未修改生产算法。

原始数据：`sweep/trials.csv`；逐格分子、分母和 95% Wilson 区间：`heatmap_aggregate.csv`。区间描述规定抽样分布下的蒙特卡洛不确定性；不是机器人跨场景的可靠性置信区间。

### 图 9：MINVO 与 Bernstein

使用生产 `extractPolynomialSegments` / `hullMap` 导出 934 个实际 MPC 原始段及全部 1168 条离线实例化曲线的多项式段，共 **14066 段**。没有改变同一段的多项式来获得更好结果。

所选展示段来自离线实例化候选，区间 **0.25–0.30 s**。按所有段中“XZ 绝对面积减少最多”的规则选择：Bernstein 约 **0.38394 cm²**，MINVO 约 **0.18497 cm²**，减少 **51.82%**。最大相对减少率另一个段为 52.69%，其绝对面积更小。选择规则和所有候选指标公开，不声称该展示段代表平均提升。

左图为使凸包厚度可见，减去该段端点连线，并以 mm 显示；这是行列式为 1 的可逆仿射剪切，面积数值仍等于原始 XZ 面积。变换参数见 `hull_display_transform.json`。原始控制点和曲线见 `selected_hull.json`，所有指标见 `hull_metrics.csv`。

此处比较二维投影面积，不是三维体积。面积更小不保证每个方向的半空间裕量更大；`hull_direction_slack.csv` 保存 361 个方向的支持裕量。其公共测试边界为曲线支持值 +1 mm，是诊断半空间，不能说成实测障碍边界。

### 图 10：真实控制输入可行性

直接从 Gazebo 控制器导出完整刚体动力学、接触、摩擦、力矩约束及 Jacobian，并保留当前电机转矩边界、基线机身加速度、接触力修改预算和足端修改预算。与只画 ±80 m/s² 盒子不同，这里有完整广义加速度/接触力/关节力矩解作为见证。

- 时间曲线：逐时刻 LP 求物理模型足端 Z 加速度上下支持界；这只是投影必要条件。
- 二维图：在实际 `uy` 上，投影 `(ux,uz)`；比较物理集合与增加全部已导出安全行后的联合集合。采用自适应 LP 支持查询，边支持差容差 10⁻⁶；每个顶点保存完整 WBC 可行见证，不把近似多边形外部一概判成不可行。
- 完整见证的等式/不等式残差除以 10⁻⁵ 数值容差，原生约束单位和原始值保留在数据中。没有将它冒称为已消元的三维 `A_u u − b_u`。
- 关节转矩使用率用 WBC 的净模型转矩除以源配置 12 Nm；不混淆硬件 PD 补偿前后的命令。

确定性选择规则：选取具有最多模型有效且实际施加硬安全约束采样的完整摆动，同分时优先靠近第一个障碍；该次先导最终选中 RF、16.225–16.625 s，**位于接近前进入口的摆动，不是已经发生在线轨迹替换的避障案例**。保留整个窗口内的失败采样。二维快照为 16.365 s 的实际安全投影，名义目标不在联合安全区域内，分配输入有可行 WBC 见证。

这支持“名义输入与联合安全约束可能不一致、需要做物理可行投影”的局部模型事实；不能证明硬件/仿真实际加速度等于分配加速度，更不能替代扰动预算标定。

### 图 11：HOCBF 安全函数和约束残差

三幅依次显示有效平面的保守 `h`、`psi1`、以及完整 6 ms 保持区间的鲁棒 HOCBF Bernstein 最小系数。使用原配置增益 20/20、加速度扰动 0.5 m/s²、位置测量误差 1 mm、速度测量误差 0.01 m/s 和 20×0.006 的采样储备。绘制实际分配输入的残差，不以足端独立过滤器的理想解替代最终 WBC 输入。

各曲线是有效平面的逐时刻最小值，最小值可能来自不同平面；逐平面法向、偏置和对应值全部在 `hocbf_planes.csv`。没有活动平面记录的区间留空。红色空心圈保留入口/求解失败；GeometryOnly 不当作完整误差管保证。

全试验导出 2183 个 WBC 快照、28892 条平面记录、1709 个有平面诊断的足端采样；其中 1707 个电机模型有效。以足端采样计，保守 h 负值 92 个，psi1 负值 557 个，保持残差负值 1542 个。这些是相关时间序列诊断，**不构成独立试验成功/失败率**。完整物理见证未发现超过 10⁻⁵ 的约束残差，但安全残差大量为负，说明“物理可执行”不等于“满足安全集合”。

## 核验与论文结论

独立 Python 重算与生产变换的曲线最大误差约 1.94×10⁻¹⁶ m；1168 条通过曲线的终端位置/速度/加速度最大误差约为 5.55×10⁻¹⁷、2.31×10⁻¹⁵、6.17×10⁻¹³；可行域顶点完整见证最大残差约 1.42×10⁻¹⁴。见 `independent_verification.json`。

三个生产 C++ 自检通过，既有 Python 场景回归 26 passed / 1 skipped。五图使用 Python / nature-figure，保留可编辑文字；每张有面板对齐、PDF 字体、文字碰撞检查及图注。默认未设置 `FIXED_TOUCHDOWN_EXPORT` 时不写实验快照；启用后的同步文件 I/O 会影响控制器墙钟性能，因此不把仪器化 WBC 延迟当作未插桩性能。

与论文初稿的对应关系：第 3.3 节的同曲线凸包表示获得数值核对；第 4.4 节的固定终端边界获得子流程证据。定理 2 本身是有前提的条件结论，本次没有验证其中“全部约束”“等待期间旧方案持续有效”和“后续共同输入持续可行”等全部前提，不能把失败样本说成推翻该条件定理，也不能将子流程通过当成完整定理在 Gazebo 成立。第 4.2–4.3 节仍缺保持区间内状态相关输入集及持续执行/后继集合证书（包括 `U_cert`）；第 5.2 节的等资源优化对照、实际走廊法向余量尚未完成，现有方向扫描只说明表示几何。

当前可支撑：固定终端边界的数值保持；规定误差分布下候选子流程的条件可行性；特定真实多项式段的 MINVO 几何收益；安全输入与全身物理可行性的局部模型关系。

当前不能支撑：64 格物理准时触地率；实际 Gazebo 同一次摆动成功激活避障更新；时间越多必然越容易通过的单调边界；MINVO 所有方向/所有轨迹均优于 Bernstein；完整重规划全程低于 5 ms；开启 HOCBF 即全程安全。

后续必要实现/验证清单：

1. 完整重放每条实际边界对应的 IK 工作空间回调与 WBC/MRT 整包准入，或实现独立复位、可控发现相位和每格 100 次的 Gazebo 试验入口，才可报告完整控制器通过率。
2. 定位并修复实际在线决策的 fixed-state / corridor / terminal 拒绝和未提交问题，再验证真实足端的接触时刻、碰撞与切换接续。
3. 拆分生产候选 QP / 连续认证 / MRT 等待 / 实际激活计时，分别报告成功与失败路径的尾部，落实在线时延预算。
4. 排查 300 ms 档位低通过率的节点/修正窗口/走廊耦合；保留原始非单调结果，不靠插值“修好”图。
5. 对 HOCBF 入口、误差管降级、联合不可行和名义回退逐项统计；校准实际执行加速度与扰动预算，才能验证执行层安全论点。

## 复现

本轮用户明确授权构建，以下仅为复现命令；不要同时运行 Gazebo 和构建。

```bash
cd /home/lee/Code/quadruped_control_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
CMAKE_BUILD_PARALLEL_LEVEL=1 MAKEFLAGS=-j1 colcon build --executor sequential \
  --packages-select ocs2_quadruped_controller fixed_touchdown_experience \
  --allow-overriding ocs2_quadruped_controller
source install/setup.bash
ros2 run fixed_touchdown_experience run_extended.py \
  --data "$PWD/src/quadruped_ros2_control/test/src/fixed_touchdown_experience/data/extended_reproduction" \
  --figure "$PWD/src/quadruped_ros2_control/test/src/fixed_touchdown_experience/figure/extended_reproduction"
```

数据目录必须不存在，禁止覆写本次原始数据。`run_extended.py` 会运行 Gazebo 先导，保留失败结果，然后执行系统 SciPy 分析、生产 C++ 扫描、凸包导出、独立核验与绘图。若没有实际摆动来源或实际安全输入快照会停止，不制造替代数据。

仅重算已有数据：

```bash
PKG=src/quadruped_ros2_control/test/src/fixed_touchdown_experience
PYTHONNOUSERSITE=1 OPENBLAS_NUM_THREADS=1 /usr/bin/python3 "$PKG/scripts/analyze_extended.py" "$PKG/data/extended_20261121"
MPLCONFIGDIR=/tmp/fixed_touchdown_mpl python3 "$PKG/scripts/verify_extended.py" "$PKG/data/extended_20261121"
MPLCONFIGDIR=/tmp/fixed_touchdown_mpl python3 "$PKG/scripts/plot_extended.py" "$PKG/data/extended_20261121" --output "$PKG/figure/extended_20261121"
```

系统 SciPy 与用户目录的 NumPy 版本不兼容，所以 LP 分析显式使用 `PYTHONNOUSERSITE=1 /usr/bin/python3`；绘图沿用已有 Python/Matplotlib。PyMuPDF 图审计路径在本机为 `/tmp/quadruped_figure_qa`。更换机器需安装相应依赖；重新绘图后须重新运行 nature-figure 的源码、字体和碰撞审计。
