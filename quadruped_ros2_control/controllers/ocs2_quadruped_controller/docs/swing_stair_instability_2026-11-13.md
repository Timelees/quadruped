# 地形摆动优化下上楼梯失衡的定位与修复（2026-11-13 晚）

## 结论

**根因是 `swing_trajectory_config.trackingPositionErrorGain` 过大，不是摆动 QP 回退。**

`useTerrainPlanning=true` 时，`LeggedRobotPreComputation.cpp:76-83` 把原本的 Z 轴速度等式约束换成三维软跟踪：

```
g = v_foot - v_ref + K * (p_foot - p_ref) = 0
```

`K` 就是 `trackingPositionErrorGain`（原值 20 1/s）。这是一个位置误差经比例增益直接转成**期望足端速度**的律：足端被台阶立板挡住时 `p_foot` 追不上 `p_ref`，误差随摆动推进线性累积，指令速度被放大成 `K * err`。K=20、3cm 残差即要求 0.6 m/s 的足端穿越速度——足端走不动，这个力就只能反作用到机身上，表现为滚转失稳。

## 实测（stair10cm，真实 keyboard_input，输入 2→3→10×w）

每种增益的通过/失败（P=完整上楼并站稳，F=楼梯段侧翻）：

| K | 结果 | 说明 |
|---|---|---|
| 0 | PP | 2/2 |
| 2 | PP | 2/2 |
| 3 | PPPPPPPP | 8/8 |
| 4 | PP | 2/2 |
| 5 | PFP | 2/3 |
| 8 | F | 1/1 |
| 10 | F | 1/1 |
| 20 | FFFFFFFPFF | 1/10（原始配置） |

剂量—反应关系明确：K≤4 稳定，K=5 临界，K≥8 必然在楼梯入口（x≈2.2-3.2 m）侧翻。

对照实验（K=20，其余不变）：

- **平地** `world:=default`：通过（x=4.80 m）——失稳需要地形障碍施加的位置误差。
- **大抬脚高度** `swingHeight=0.14`：仍失败——单纯抬高足端不能解决。
- **跟踪权重降到 1.0**：仍失败——权重只改软约束的惩罚强度，位置误差反馈律本身仍在，K 才是决定项。
- **`terrainGeometryMode=0`（离散采样）**：仍失败（x=2.36 m）——不是 MINVO 包络的问题。

## QP 回退率的真实含义（重要：不是这次的主因）

各运行中 `Swing QP` 回退率都高达 60-70%，且 `row=0`（摆动起点固定控制点）占绝大多数：

| 运行 | QP 成功 | 回退 | 其中 row=0 |
|---|---|---|---|
| K=20 原始 | 1505 | 2563 | 2206 |
| K=0 通过 | 2572 | 4836 | 4836 |
| K=3 通过 | 3219 | 6229 | 6229 |

**通过的那些运行回退更多**。所以回退不是失稳原因：它反映的是接触端点与"地形走廊下界"之间的建模冲突（端点恰好落在地表，而下界按球半径外扩后取到台阶上表面），但回退只把名义样条原样保留，并不会自己让机身失稳。

具体而言 `row=0` 的残差中位数只有 -0.6 mm，且大多发生在上楼之前（x<2.0 m，1661/2206 次），说明它主要是数值/接触语义边界问题，不是"落点低于地面 2.5cm"这类几何错误。

我曾尝试"把接触段的地形下界钳位到接触点下方表面高度"来消除 row=0 回退。实测该改动**未能减少 row=0 失败**，反而把最坏残差从 -27 mm 放大到 -210 mm，因此已完整回退，未保留。

## 应用的改动

`cyberdog_description/config/ocs2/task.info`：

```
trackingPositionErrorGain     20.0  ->  3.0
```

单行配置修改，无代码改动。取 3.0 而非临界值 5.0，留出 1.5 倍以上余量（3.0 下 8/8 通过，5.0 已出现 1/3 失败）。

## 验证

| 场景 | 结果 |
|---|---|
| stair10cm ×2 | 通过，x=4.83/4.80 m，末态 roll=+0.208/-0.546 |
| default（平地） | 通过，x=4.87 m |
| stair15cm ×2 | **失败**，x≈2.1 m 侧翻 |

15cm 台阶在 K=20（原始配置）下**同样失败**（x=2.17 m），因此不是本次改动引入的回归，而是当前抬脚高度/落足规划对 15cm 台阶能力不足，属未解决项。

## 未解决的问题

1. **QP 接触端点回退**：`row=0` 的建模语义仍需正确处理——接触点应当落在表面而不是"表面 + 球半径外扩上界"。本轮尝试的方案已证伪，需要重新设计（例如接触段改用 Bezier 精确端点并单独约束端点所在棱柱，或让下界随摆动进度在接触段渐变）。
2. **15cm 及以上台阶**：需要提高 `swingHeight`、改进落足点选择或增加机身高度自适应，本轮未处理。
3. **未采集接触力**：无法从接触力证据区分"足端撞立板"与"动力学耦合"，上述机制判断基于控制律形式与增益扫描，非直接力矩测量。

## 复现方式

原始数据在 `log/swing_fix_20261113/`：

- `orchestrate.py`：启动独立 Gazebo（`ROS_DOMAIN_ID=51`、独立 `GZ_PARTITION`），临时改写 `task.info` 后运行，结束后逐字节恢复。
- `run_gt.py`：通过 pty 给真实 `ros2 run keyboard_input keyboard_input` 喂 2→3→10×w，按 `/Ground_Truth` 记录并以姿态阈值（|roll|>0.65 或 |pitch|>0.7）判定失败。
- `summarize.py`：汇总所有运行的配置、结果与 QP 统计。
- `task.baseline_gain20.info`：改动前的完整配置备份。
